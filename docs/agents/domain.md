# Domain docs

## Before exploring

Read root `CONTEXT.md` and ADRs in `docs/adr/` relevant to the work.

If these do not exist, proceed silently. Domain documentation is
created lazily through domain-modeling as terms and decisions resolve.

## Layout

Single-context: one root `CONTEXT.md` and root `docs/adr/`.

## Vocabulary

Use domain terms as defined in `CONTEXT.md`, including in issues,
proposals, hypotheses, and test names. Note genuine glossary gaps
for domain-modeling.

## Decisions

Explicitly flag any proposal that contradicts an existing ADR,
identifying the ADR and why the decision merits reopening.
